# KiCad Libs and Templates

This directory contains a set of common symbols, footprints, 3D models, and templates
that we use during hardware development. Everything here is a continuous work-in-progress,
and anything can change at any time.

We specifically allow third party models because they're typically just for fitment
purposes, but the symbols and the footprints should always be hand-drawn. This is because
imported/autogenerated footprints are typically either A. not conducive to clean layouts
(like symbols will have all their pins placed in a counterclockwise order instead of
in an order that makes sense for a schematic) B. completely dysfunctional (it is impossible
to create a universal "model" for a footprint that fits all the nuances of every single
CAD software, which is what a lot of what the online cataloging sites try to achieve).


## Included Footprints

Typically, we strive to have control over as many of our own symbols, footprints, and models
as possible. This is because KiCad regularly changes them, and oftentimes, their work is a bit
off as everything is crowdsourced, so testing for any given part is dubious at best.

Additionally, certain parts like footprints depend _heavily_ on the fab and their capabilities,
and obviously everyone isn't designing for JLCPCB.

### Connector_Molex

Here we keep the ~30 single row through-hole Molex Clik-Mate connectors. 15 horizontal, 15 vertical,
numbered 1 to 15 pins, with the locator peg. 

### Connector

This one is just misc connectors. Oftentimes we will want to modify the silkscreen on a stock KiCad
part, and when you modify a KiCad footprint, its best to save your modifications to your own library.

It also contains the one footprint we did import so far from LCSC, the `GT-USB-7051`. It was wrong
OOTB and we had to fix it (see above).

### Graphic

APRL logo for branding purposes, and some loose pads for probing/heat dissipation if needed.

### Misc

Our modified mounting hole and a custom net tie so far. Just a dumping ground for something
which doesn't fit a good definition of the other libraries.

### Module

These are just various small assemblies. Buzzers, buttons, rotary encoders, etc.

### Package_QFN

For QFN packages we will typically place thermal vias toward the outsides of pads
and modify pad dimensions to meet our own standards. As a result, we store the
modified footprints here.

### Package

Same as `Package_QFN`, but not for QFN packages.

### Passive

These are just various passive components. We use Worthington's perfect footprints
for passives.

## Templates

We keep 2 templates: 1 for schematics, and 1 for layouts. The only difference
is the layouts display the stackup used, which is typically JLCPB 7628.

Unlike the original KiCad sheets, ours better embed the engineering workflows
we envision for this club. This means someone:

1. Draws something
2. Gets it reviewed
3. Gets it approved and ordered
4. Assembles it ("As built" in the revision table)
5. Makes revisions as necessary

Because there are so many custom variables, we just don't use the embedded KiCad
ones that you get just by clicking on a frame.

## Models

3D models can be grabbed from anywhere. We just dump them all in this directory,
to make it easy to filter them for `git lfs`.
